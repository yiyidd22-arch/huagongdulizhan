> 文档日期：2026-06-08  
> 适用项目：独立站 `huagongdulizhan` + 化工管理系统 `gaoyuan.zwstone.cn`

---

## 一、整体架构（三个系统）

本项目由 **三套互相配合的系统** 组成：

| 系统 | 作用 | 地址 / 位置 |
|------|------|-------------|
| **化工管理系统（CMS）** | 后台发新闻、管订单等业务 | https://gaoyuan.zwstone.cn |
| **独立站（官网）** | 对外展示的企业官网 | https://huagongdulizhan.pages.dev |
| **Cloudflare 数据层** | 存新闻 JSON、加速全球访问 | R2 桶 `gaoyuan-news` + Worker |

```
┌─────────────────────────────────────────────────────────────────┐
│  化工管理系统（宝塔服务器 43.153.118.218）                        │
│  https://gaoyuan.zwstone.cn                                     │
│                                                                 │
│  你在后台「发布 / 撤销 / 删除」新闻                                │
│       ↓                                                         │
│  后端 NewsSyncService 自动调用 Webhook（约 1 秒内发出）           │
└──────────────────────────┬──────────────────────────────────────┘
                           │ POST（带密钥）
                           ↓
┌─────────────────────────────────────────────────────────────────┐
│  Cloudflare Worker：gaoyuan-news-sync                           │
│  https://gaoyuan-news-sync.yiyi-dd22.workers.dev                │
│                                                                 │
│  1. 接收 CMS 推送的本地图片（base64）→ 写入 R2 images/           │
│  2. 从 CMS API 拉取全部已发布新闻                                 │
│  3. 生成 list.json、detail/{id}.json（图片路径改为本站）         │
│  4. 写入 R2 存储桶 gaoyuan-news                                  │
└──────────────────────────┬──────────────────────────────────────┘
                           │
                           ↓
┌─────────────────────────────────────────────────────────────────┐
│  Cloudflare Pages（独立站）                                      │
│  https://huagongdulizhan.pages.dev                              │
│                                                                 │
│  新闻页读取本站 /news-data/list.json（同源 CDN，不请求后台 API）   │
│  Pages Function 从 R2 实时提供 JSON 文件                         │
└─────────────────────────────────────────────────────────────────┘
```

**核心原则：**

- **新闻内容** 存在 Cloudflare R2，不是 GitHub 代码里，也不是每次打开页面去请求后台 API。
- **网站代码**（页面、样式、布局）仍在 GitHub，通过 `git push` 触发 Cloudflare 构建。
- **发新闻** 不需要 `git push`，也不需要等 2–5 分钟整站 rebuild。

## 二、两类「更新」要分开理解

| 你要做的事 | 操作方式 | 是否需要 git push | 大约多久生效 |
|------------|----------|-------------------|--------------|
| **发布 / 编辑 / 删除新闻** | 在化工管理系统后台操作 | **不需要** | **5–30 秒**（自动同步到 R2） |
| **改独立站页面、样式、文案** | 本地改代码 → `git push origin master` | **需要** | 2–5 分钟（Cloudflare 自动构建） |
| **手动补救同步新闻** | 本地运行 `npm run sync:news` | 不需要 | 约 30 秒–1 分钟 |

## 三、新闻发布的完整流程（自动）

```
1. 登录 https://gaoyuan.zwstone.cn/#/news/list
2. 新建 / 编辑新闻 → 点击「发布」
   （或撤销发布、删除已发布新闻）

3. 后端 houduan 检测到变更
   → NewsSyncService.triggerSync()
   → 读取 uploads/news/ 下已发布新闻的封面/配图（本地磁盘）
   → POST 到 Cloudflare Worker（带 NEWS_SYNC_SECRET + images 数组）

4. Worker 执行：
   a. 将 images 写入 R2：images/{文件名}
   b. GET https://gaoyuan.zwstone.cn/api/news/public?limit=500
   c. 把 JSON 里的 coverImage / images 改写为 /news-data/images/{文件名}
   d. 写入 R2 桶 gaoyuan-news（list.json、detail/{id}.json 等）

5. 用户访问独立站 https://huagongdulizhan.pages.dev/news
   → 浏览器请求 /news-data/list.json 和 /news-data/images/*.jpg
   → Pages Function 从 R2 读取并返回（文字 + 图片均来自本站 CDN）
   → 页面显示最新新闻
```

**撤销 / 删除新闻：** 同样在后台操作即可。Worker 会重新拉取「当前已发布列表」，被撤销或删除的新闻不会出现在 JSON 里，独立站刷新后也不再显示。

## 四、独立站代码部署流程（Git）

当你修改了独立站的页面、组件、样式时：

```powershell
cd d:\huagongdulizhan
git add .
git commit -m "更新说明"
git push origin master
```

推送后 Cloudflare Pages 自动：

1. 从 GitHub 拉取代码  
2. 执行 `npm run build`（构建时会删除 `out/news-data`，避免静态文件覆盖 R2 实时数据）  
3. 部署到 https://huagongdulizhan.pages.dev  

**注意：** 改代码的部署 **不会** 更新新闻内容；新闻由 R2 单独维护。

## 八、故障排查

| 现象 | 可能原因 | 处理办法 |
|------|----------|----------|
| 新闻封面仍指向 gaoyuan.zwstone.cn | CMS 未更新或未重新触发同步 | 重新部署 houduan（含图片推送逻辑），后台编辑并保存已发布新闻 |
| 图片 URL 404 | R2 无对应 images/ 文件 | 查 CMS 后端日志是否「N 张图片」同步成功；手动 `npm run sync:news` |
| 后台发了新闻，独立站没更新 | Webhook 未触发或 Worker 失败 | 服务器查后端日志；手动 `npm run sync:news` |
| 独立站新闻页空白 | R2 无数据或 Function 未部署 | 访问 `/news-data/list.json` 看是否 200 |
| 手动 sync 失败 | 本地网络连不上 CMS API | 在服务器上 curl Worker，或重试 |
| git push 后新闻消失 | 旧版静态 JSON 覆盖了 R2 | 已修复：构建时会 `prune-news-static-out` |
| 下次部署 CMS 后 Webhook 失效 | docker-compose 缺 env | 确认 `NEWS_SYNC_*` 两行在 `docker-compose.prod.yml` |

**浏览器调试：** 打开独立站 `/news` → F12 → Network → 查看 `list.json` 请求是否 200、内容是否有数据。

## 九、与旧方案的区别（供参考）

| | 旧方案（已废弃） | 现方案 |
|---|----------------|--------|
| 新闻数据来源 | 浏览器实时请求 `gaoyuan.zwstone.cn/api` | 读本站 `/news-data/*.json`（R2 + CDN） |
| 新闻图片 | 从 CMS 域名加载 | 同步到 R2，从本站 `/news-data/images/` 加载 |
| 发布新闻后要做什么 | 刷新即可（但 API 慢、易失败） | 后台自动同步，约 5–30 秒 |
| 是否需要 git push 发新闻 | 否 | 否 |
| 全球访问速度 | 依赖后台服务器 | Cloudflare 边缘 CDN，更快 |

## 十、一句话总结

> **改网站 → `git push`；发新闻 → 后台点发布，文字+图片自动同步到 R2，独立站几秒后刷新即可。**

两套系统、两种更新方式，互不干扰。
